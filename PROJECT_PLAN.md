# FoodWise AI – Project Plan

## Requirements analysis
Decision-support system (SDG 12 primary, SDG 2 secondary) that predicts meal demand (regression),
food-waste risk (3-class classification), derives surplus/waste metrics, and gives *recommendations only*
(no automatic redistribution). Delivered as a Streamlit app backed by SQLite.

## Key design decisions
| Decision | Rationale |
|---|---|
| Dataset is **synthetic**, generated by a documented simulator (`src/data/generate_data.py`) | No public dataset matches the schema. Always labelled synthetic. |
| Light data-quality issues (missing values, duplicates) are injected into the *raw* file | So that validation/cleaning steps are exercised honestly; documented. |
| **Time-based** train/test split (last 20 % of dates) + `TimeSeriesSplit` CV | Avoids look-ahead leakage in time-series data. |
| `meals_prepared` is **not** a demand-model feature | Demand must not depend on the supply decision; it is used for surplus/risk only. |
| Model selection by CV score on the training period (RMSE / macro-F1) | Test set is only for final reporting. |
| Naive baselines reported (previous-week demand, majority class) | A model must beat a trivial baseline to be meaningful. |
| Streamlit only, no FastAPI | A single in-process `PredictionService` is sufficient; an API adds no value here. |

## Phases
1. Structure + config  
2. Data: generation → validation → cleaning → EDA  
3. Features + two ML pipelines, evaluation, serialization  
4. SQLite database (history, predictions, prediction logs)  
5. Prediction service + business logic  
6. Streamlit UI (7 pages)  
7. Tests  
8. Run everything end-to-end, fix errors  
9. Documentation (from *actual* metrics)

## Definition of done
Pipeline runs with one command, tests pass, app boots and every page renders, forms return real model predictions.
